# 桌面应用交互标准

派生应用在写首个业务页面前先读本页，再读[应用开发与交付标准](./application-standard.md)。它把桌面优先产品最容易后期返工的边界提前固定：窗口壳、工作区、浮层、设置同步、原生行为与真实运行时验收。

> 这不是要求换用 Electron 或原生 UI。Tauri + Vue 足以实现以下标准；关键是把 WebView 当作桌面应用的一层，而不是直接把网页放进窗口。

## 一、在实现前写下的交互契约

在产品协议和首个界面实现前，写清以下决定；未决定的项目不要先堆页面：

| 决定 | 必须说明 |
| --- | --- |
| 主窗口壳 | 是否自绘标题栏、内容是否延伸到标题栏、哪些区域可拖动、窗口控制的位置 |
| 工作区 | 左侧导航、主内容、右侧检查器是否存在；谁拥有各区宽度、滚动和最小尺寸 |
| 对象编辑 | 一个对象的查看、编辑、删除、完成等动作是否在同一检查器中切换状态 |
| 浮层 | 哪些是轻量 Popover，哪些是 Sheet 或确认框；它们的关闭、焦点、滚动锁定由谁统一管理 |
| 偏好 | 主题、字号、布局宽度等设置的唯一存储、默认值、迁移与多窗口同步方式 |
| 原生行为 | 刷新快捷键、右键菜单、关闭/隐藏、托盘、拖放、全局快捷键的产品规则 |
| 验收尺寸 | 目标平台、正常窗口、最小窗口、短窗口、窄屏与高 DPI 的代表性尺寸 |

不要把这些决定藏在某个页面组件的局部状态中。工作区、窗口与用户偏好属于应用级协议；业务页面只消费它们。

## 二、窗口和工作区：只有一个布局所有者

- 主窗口必须先决定系统装饰或自绘标题栏。若选择自绘，标题栏、拖拽区、窗口控制和内容背景由同一个应用壳实现；若保留系统标题栏，视觉设计应把它视作窗口的一部分，不能假定内容能与它无缝融合。
- 应用壳统一管理 `sidebar / main / inspector / overlay` 的可见性、尺寸、最小宽度与过渡。页面组件不能分别用绝对定位或负 margin 推挤其它区域。
- 桌面侧栏应支持产品定义的固定宽度或受限拖拽宽度；拖拽范围、最小/最大宽度和持久化键集中定义。窄窗口先收起或改为抽屉，不能让侧栏出现横向滚动条。
- 一个可滚动页面只保留一个明确的垂直滚动容器。窗口壳使用 `height: 100dvh`（或等价原生窗口高度）和 `overflow: hidden`；只有内容区或面板主体负责 `overflow: auto`。固定头部、底部操作栏和浮层不应被页面滚出视口。
- 任何可调整大小的面板或窗口都要在每次尺寸变化后尊重最小尺寸、最大尺寸和安全边距；不能依赖初始渲染时的像素测量。

## 三、对象面板：查看与编辑是一条路径

- 对同一对象只保留一个主检查器。默认是查看态；编辑动作在原位切换为编辑态，保存或取消后回到查看态。
- 不能同时维护“详情抽屉”和“编辑弹窗”两套独立信息架构。模态框只用于确认破坏性操作、需要独立上下文的创建流程，或小窗口确实放不下的任务。
- 检查器的标题、关闭、主要动作、滚动主体和固定底部操作栏属于同一个面板；底部栏禁止用负外边距扩展宽度，避免横向溢出和关闭后残留。
- 从列表或日历进入检查器时，面板从对应视觉方向淡入/滑入；关闭时反向退出。动画只改变 `opacity` 和 `transform`，不动画宽度、文档流或根容器位置。
- 同一对象任何时刻只能有一个激活展示面：打开编辑态前关闭查看态，关闭面板后清除选中对象。该不变量应有针对性测试。

## 四、浮层、手势与输入：共享生命周期，不共享业务

- Popover、Sheet、菜单和确认框统一由应用级浮层层管理 `z-index`、焦点回收、`Escape`、外部点击、滚动锁定与退出动画。业务组件只提交操作和接收结果。
- 指针手势要区分 `pointerup`、拖拽、失去指针捕获和真正的“点击外部”。不得把任何 `lostpointercapture` 一律当作取消，否则日历轻量创建卡会在用户松开鼠标时消失。
- 日历/时间轴点击空白处应先显示锚定在点击位置的轻量创建卡；只有明确取消、点击卡外、`Escape` 或成功提交才关闭。创建失败保留输入与可恢复错误。
- 支持拖放的日程或任务必须提供开始、预览、落点校验、提交、失败恢复与撤销。仅在数据层支持改期不等于用户可拖拽改期。
- 输入框使用共享基础组件和 token：真实 label 与 placeholder 分工，紧凑高度，统一焦点边框和圆角。不要在页面内各自调高输入框或重复标题、label、placeholder 的同一份文案。
- 同级列表默认用间距、hover 和选中态表达层级；只在类别切换或内容关系确实需要时才用分割线。选中、悬浮和按下态必须有不同但克制的表面和阴影，阴影跟随圆角轮廓，不能出现方形背景块错位。

## 五、设置、主题和跨窗口状态：一个事实源

- 主题、字号、透明度、侧栏宽度和其它应用级偏好只能通过一个设置适配器读写；组件不直接读写 `localStorage`。
- 任何额外 WebView 或设置窗口必须从宿主存储读取相同偏好，并经 Tauri 事件或共享 store 向所有窗口广播更新。不能依赖浏览器 `storage` 事件跨 WebView 同步。
- 主题切换一次性更新全部可见根节点和浮层；每个主题都验证主窗口、设置窗口、抽屉、菜单、输入框、空状态和深浅模式。
- 设置页面和主应用使用同一个应用壳、token 与滚动规则。设置内容变长时只能让设置内容区滚动，不能带动整窗出现空白区域或让侧栏错位。
- 字号设置应定义粒度、默认值、最小/最大值和持久化策略；它改 token，而不是为若干文字单独写 font-size。

## 六、原生行为不是浏览器默认行为

- 在目标桌面运行时显式决定 `F5`/`Ctrl+R`、右键菜单、窗口关闭、最小化和拖放规则。保留、禁用或替换都可以，但不能无意暴露浏览器的刷新、另存为和打印菜单。
- 右键菜单按目标对象提供有限的领域操作，例如任务可有“编辑、完成、延后、删除”，空白时间格可有“新建日程”。没有可用操作时不显示菜单。
- 原生快捷键、托盘和通知属于能力模块：同时对齐模块配置、运行时能力、Rust feature、插件注册和 Tauri capability；Web 运行时要有清晰降级。
- 多窗口、托盘与关闭策略必须在打包后的应用中验证。Web 预览通过只证明 Web 路径，不能证明桌面行为。

## 七、首个功能的桌面验收清单

在增加第二个复杂页面前，先让一个对象的完整旅程通过下列检查：

- [ ] 正常窗口、最小窗口、短窗口和高 DPI 下，主窗口没有根页面纵向或横向溢出。
- [ ] 侧栏、主内容和检查器的显示/隐藏不改变彼此的最终位置；动画过程没有闪烁、抖动或重复面板。
- [ ] 打开对象、切换编辑、保存、取消、关闭和删除后，始终只有一个对象面板可见，选中状态与面板一致。
- [ ] 每种浮层可用键盘进入、`Escape` 关闭、焦点回到触发控件；长内容只在预期区域滚动。
- [ ] 主题、字号和布局偏好在关闭重开后保留；有多窗口时，修改能即时同步。
- [ ] 日历或时间轴至少验证点击新建、取消、提交、拖动改期、无效落点与撤销。
- [ ] 真实桌面运行时验证 F5、右键、窗口关闭/托盘、滚轮和触控板滚动；浏览器默认菜单没有意外出现。
- [ ] 执行 `npm run verify`；涉及 Rust/Tauri 运行时再执行 `npm run rust:verify`，并人工走完上述目标平台旅程。

记录每项的运行时、窗口尺寸、通过/阻塞状态和截图或自动化证据。静态截图、Web 构建成功或进程存活都不能替代真实交互验收。
